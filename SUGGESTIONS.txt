AI HAIRSTYLE RECOMMENDER – IMPLEMENTATION PLAN (PRACTICAL)

GOAL
Give users a face/hair scan, then show hairstyle try‑on results. If a suitable style isn’t found, the user can pick from your own haircut library (manual selection) and still try it on.

PHASE 1: USE EXISTING HAIRSTYLE LIBRARY (FAST MVP)
1) Mobile captures a camera photo (already implemented).
2) Upload image to /api/ai_scan.php (multipart/form‑data).
3) Backend runs face + hair analysis:
	- Face shape detection (oval/round/square/heart)
	- Hair type detection (straight/wavy/curly/coily)
4) Query hairstyleVariants table to match (faceShape, hairType).
5) Return top 6–12 variants for immediate display.

PHASE 2: USER‑CHOSEN HAIRCUT TRY‑ON (LIBRARY EXPANSION)
If user doesn’t like results:
1) Show full haircut library list (haircuts table + images).
2) User selects a haircut.
3) Backend generates try‑on using image‑to‑image (prompt + controlnet/segmentation) OR overlays a prepared variant.
4) Save result as a new hairstyleVariants row.

RECOMMENDED TECH STACK
Face + Hair Analysis:
- MediaPipe Face Mesh (local) OR Azure Face API (cloud)
- Hair type classifier (simple ML model or heuristic based on texture)

Try‑On Generation (Pick One):
Option A: Pre‑generated assets only (cheap, fast)
- Make variants for each haircut x faceShape x hairType
- Store images in /assets/ai/ or cloud storage

Option B: Generate on demand (higher quality)
- Use Stability/Replicate SDXL img2img + hair segmentation mask
- Store generated output in hairstyleVariants for reuse

DATABASE USAGE
- haircuts: list of base styles
- hairstyleVariants: all generated or pre‑made outputs
- favorites: user saves a try‑on
- auditLogs: log AI events for analytics

API ENDPOINTS
- POST /api/ai_scan.php (multipart) -> returns variants
- POST /api/ai_tryon.php (future) -> generate try‑on for selected haircut
- GET /api/haircuts.php (future) -> list haircut library

QUALITY + COST CONTROL
- Cache outputs: if a variant exists, reuse it
- Limit generation: max N new variants/day
- Offer manual selection when AI cannot detect face/hair

USER FLOW (SIMPLE)
1) Scan face
2) See auto recommendations
3) If none fit, choose from haircut library
4) Try‑on generated or pre‑made
5) Save favorite

NEXT BUILD STEPS
1) Seed haircuts + hairstyleVariants
2) Implement /api/ai_scan.php with real provider
3) Add /api/haircuts.php for library list
4) Add try‑on endpoint or use pre‑generated assets

PROVIDER RECOMMENDATION (BEGINNER‑FRIENDLY)
Option 1 (Easiest + practical):
- Face/hair detection: MediaPipe Face Mesh (runs locally)
- Try‑on generation: Replicate (SDXL img2img) – simple REST API
- Pros: simple API, fast to test, lots of examples
- Cons: paid after free credits

Option 2 (Microsoft stack):
- Face analysis: Azure Face API
- Try‑on: Replicate or Stability AI
- Pros: reliable detection
- Cons: more setup/keys

- Use /api/haircuts.php to list styles

- Populate hairstyleVariants with real images
