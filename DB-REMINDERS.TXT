SYSTEM RULES (DON'T BREAK THESE)
1) All apps (mobile, web, kiosk) use PHP API only.
2) Flutter/web NEVER access MySQL directly.
3) Keep data normalized; avoid duplicates.

CORE TABLE PURPOSES
users
- All system users; role is stored in users.role (enum)

roles / userRoles
- Role dictionary + optional mapping table

barbers
- Barber profile linked to users

services / serviceCategories
- Service library + categories

haircuts
- AI hairstyle library (faceShape + imagePath + isActive)

favorites
- User favorites (haircut or barber)

scheduleTemplates / scheduleExceptions
- Recurring schedules + exceptions

appointments / appointmentServices
- Appointment records + related services

walkIns
- Walk‑in tracking (separate from appointments)

payments / transactions
- Payment records + references

feedback / notifications / deviceTokens
- Ratings, messages, device tokens

aiRecommendations
- Store AI recommendations per user for analytics

appointmentStatusHistory
- Track status transitions

auditLogs
- System audit trail

AI HAIRSTYLE SCANNER FLOW (MAIN FEATURE)
1) Mobile opens camera and captures image.
2) Upload to /api/ai_scan.php (multipart/form-data).
3) Backend analyzes face/hair and maps to haircuts.faceShape.
4) Return matching haircuts (imagePath).
5) Save recommendations to aiRecommendations.

TABLES USED BY AI SCAN
- haircuts
- aiRecommendations
- favorites (when user saves)

DATA CONSISTENCY NOTES
- All booking/payment/feedback link to appointments.
- All AI results come from haircuts library.
- No duplicated service or haircut names in other tables.
